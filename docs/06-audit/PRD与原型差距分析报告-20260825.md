## 一、核心结论：PRD 与原型严重脱节

PRD v1.3.0 写于 2026-08-23，描述的是**讲师/助教/店长/店员/分成/打卡/红包/提现的完整体系**。但 2026-08-25 一天内，原型被多轮删除/恢复/再删除，最终业务逻辑已大幅偏离 PRD。

**PRD 仍描述旧体系，原型已变成删减后的混合状态——两者对不上，这就是"乱"的根源。**

### C. 业务闭环差距（严重）

> 「内容生产（讲师→课程→审核）→ 营期组织（营期→排课→招募）→ 学员学习（报名→支付→学习→**打卡**→证书）→ **商业闭环（分成→结算→退款）**→ 激励闭环（积分→**红包**）」

> 「课程创建（无讲师绑定）→ 营期组织（无分成配置）→ 学员学习（报名→支付→学习→证书，**无打卡**）→ **无商业闭环**→ 激励（仅积分，**红包半残留**）」

**PRD 描述的"商业闭环"和"激励闭环"在原型里都断了。**

## 三、差距根因分析

### 根因 1：PRD 没有随原型改动同步更新
- PRD v1.3.0 写于 2026-08-23，之后 2026-08-25 一天内原型被改了 20+ 轮
- 所有改动都只在原型代码和 daily memory 里，**PRD 一行没动**
- 导致 PRD 还在描述旧体系，新人/研发按 PRD 实现会做出和原型完全不同的东西

### 根因 2：改动指令反复（删→恢复→再删）
- 上午：移除店长/店员/讲师字段
- 中午：git checkout 误删全部 UI + 业务逻辑
- 下午：恢复 UI，restore 团队把业务逻辑也删了
- 用户澄清："恢复到删之前" → add 团队又加回来
- 后来又决定：讲师/助教端停用、分成/打卡移除
- **原型经历 4 次反向操作，PRD 没有任何一次同步**

### 根因 3：PRD v1.3.0 本身就基于"10 项跨域决策"（已被推翻）
- PRD §10A 的 C4 决策"店长=主讲/店员=助教"已被用户放弃
- PRD §10A 的 C5 决策"课程订单走 CommissionBill 归讲师"已被用户放弃
- PRD §10A 的 C6 决策"课程分成线下打款"已被用户放弃
- **PRD 的核心决策表已经全部失效，但 PRD 没标"已废弃"**

## 四、修复建议

### 建议 1：PRD 需要出 v1.4.0 修订版
- 标注"讲师端/助教端 APP 已停用 2026-08-25"
- 标注"店长/店员角色体系已移除"
- 标注"分成配置/打卡功能/红包体系/提现功能 已移除"
- 修订核心链路为：「课程创建 → 营期组织 → 学员报名支付学习证书 → 退款（无分成/无打卡/无红包/无提现）」
- §10A 跨域冲突决策表全部标"已废弃 2026-08-25"

### 建议 2：明确"原型当前业务逻辑"单一事实源
当前原型实际业务逻辑（用户最新指令"恢复到删之前"=基于 SugarMate 但删减后）：
- 角色：学员端 APP + PC 后台管理员（无讲师/助教端）
- 报名流程：营期详情 → 报名 → 审核 → 支付 → 签合同 → 学习
- 学习流程：视频播放 → 答疑 → 测验 → 证书（无打卡）
- 退款流程：申请 → 审核 → 退款（无分成冲减）
- 无商业闭环（无分成/无结算/无打款）
- 无激励闭环（仅积分，无红包/无钱包/无提现）

### 建议 3：SugarMate 参考关系重新定义
- SugarMate 原版有完整体系，但 SaaS-Class 已主动删减
- 不能再"1:1 对齐 SugarMate"，应标"基于 SugarMate 简化版"
- PRD §3.1 的"1:1 对齐"承诺（BG-COURSE-06）已失效
