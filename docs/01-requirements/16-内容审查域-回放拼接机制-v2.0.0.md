# 16-内容审查域 · 回放手动拼接机制 v2.0.0

> **文档类型**：业务规则定义（表格化汇总）
> **适用范围**：SAAS 内容审查域，直播结束后回放片段的人工拼接处理
> **审阅人**：用户
> **状态**：✅ 已定稿（2026-08-19 用户裁决 v2.0.0）
> **关联规则**：BR-AUDIT-024（手动拼接）/ BR-AUDIT-025（双文件保留）/ BR-AUDIT-027（违规标记复审）/ BR-AUDIT-028（片段文件独立审核）/ BR-AUDIT-029（一一对应）/ BR-AUDIT-030（先审后拼与先审后发）

---

## 一、核心规则（一句话）

> **每个回放片段与每个回放文件都单独审核通过 → 勾选序号一一对应的片段和文件 → 触发拼接 → 人工发布。**

v2.0.0 由 v1.0.0「自动拼接」改为「手动拼接」：运营在回放页主动审核每个文件、勾选对应片段/文件、点拼接按钮生成完整文件，再发布对用户可见。

---

## 二、机制总览

### 2.1 触发时机

| 触发条件 | 时机 | 备注 |
|---|---|---|
| 推流中断超过 N 秒 | 直播中（实时） | 产生新片段，`segment_index++` |
| 直播状态：live → ended | 直播结束 | 系统判定结束，回放片段+回放文件均已生成 |
| **运营手动触发拼接** | 回放页 | 由运营点「拼接」按钮触发（v2.0.0 关键改动） |
| **运营手动发布** | 回放页 | 拼接完成后，由运营点「发布」触发（v2.0.0 关键改动） |

> v1.0.0 由系统自动拼接+自动发布；v2.0.0 改为全部由运营在回放页手动完成，避免系统误判。

### 2.2 拼接流程（5 步）

| 步骤 | 动作 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| ① 文件审核 | 运营逐个点「审核通过」 | 回放文件列表 | 每个文件 review_status=approved | 任一文件未通过 → 阻塞后续 |
| ② 勾选对应 | 运营勾选序号一一对应的片段+文件 | 已审核片段/文件 | 勾选集合 size 相等 & index 完全一致 | 不匹配 → 拼接按钮锁定 |
| ③ 拼接校验 | 系统校验：所有文件已审核 & 勾选集合 index 一一对应 | 勾选集合 | 校验通过 | 校验失败 → 提示具体原因 |
| ④ 生成完整文件 | FFmpeg concat 拼接源码 + 擦音 | 勾选集合 | 完整回放文件（源码+擦音后） | merge_status=failed |
| ⑤ 发布 | 运营点「发布」 | 完整回放文件 | 回放对用户可见 | 任何前置条件缺失 → 按钮锁定 |

### 2.3 文件产出

| 文件 | 类型 | 是否可播放 | 是否对外 | 用途 |
|---|---|---|---|---|
| **回放文件（片段级）** | 单片段擦音版 | ✅ 可播放 | 租户 + 运营 | 拼接前的中间产物；未审核不可参与拼接 |
| **源码文件（片段级）** | 单片段未擦音 | ✅ 可播放（只读） | 租户 + 运营 | 对账 / 审计 / 复核违规内容 |
| **完整源码文件（拼接后）** | 多片段拼接未擦音 | ✅ 可播放（只读） | 租户 + 运营 | 拼接后产物，对账 |
| **完整回放文件（拼接后）** | 多片段拼接已擦音 | ✅ 可播放 | 租户 + 观众可见 | 对外发布版本 |

### 2.4 拼接状态（merge_status → merge 进度）

| 状态 | 含义 | UI 展示 | 后续动作 |
|---|---|---|---|
| `pending` | 未拼接（默认） | 「未拼接」灰色标签 | 运营可点「拼接」按钮触发 |
| `merging` | 拼接中 | 「拼接中」橙色标签 + 进度条 | 系统处理中，按钮禁用 |
| `completed` | 拼接成功 | 「已拼接」绿色标签 + 展示完整文件 | 运营可点「发布」 |
| `failed` | 拼接失败 | 「拼接失败」红色标签 + 失败原因 | 提示运营联系技术；不进入发布 |

### 2.5 拼接失败处理

| 失败类型 | 表现 | 处置 |
|---|---|---|
| 片段缺失/损坏 | 单/多片段无法读取 | `merge_status=failed`，提示「片段 N 损坏」 |
| 拼接超时 | 重试 N 次仍超时 | `merge_status=failed`，提示运营 |
| **校验失败（v2.0.0 新增）** | 勾选集合 size 不等或 index 不匹配 | 拼接按钮直接锁定，无需进入处理流程 |

## 三、片段与文件独立审核

### 3.1 每个片段单独审核

| 审核对象 | 审核字段 | 审核动作 |
|---|---|---|
| ReplaySegment | `review_status` | 待审核 / 已审核 / 已拒绝 |
| | `reviewer` / `reviewed_at` | 审核人 + 审核时间 |

> 仅 `review_status=approved` 的片段可在回放页勾选参与拼接。

### 3.2 每个文件单独审核

| 审核对象 | 审核字段 | 审核动作 |
|---|---|---|
| ReplayFile | `review_status` | 待审核 / 已审核 / 已拒绝 |
| | `reviewer` / `reviewed_at` | 审核人 + 审核时间 |

> 每个回放文件卡片有「审核通过」按钮（v2.0.0 新增），点击后 review_status → approved，文件可参与拼接。

### 3.3 审核状态机

```
[pending_review] --运营点「审核通过」--> [approved]
                  --运营点「拒绝」--> [rejected]
[rejected] --运营重审通过--> [approved]
[approved] --不允许回退到 pending_review（防误操作）-->
```

## 四、一一对应规则（BR-AUDIT-029）

### 4.1 序号对应

| 字段 | 片段 | 文件 | 对应关系 |
|---|---|---|---|
| 序号 | `segment_index`（1..N） | `file_index`（1..N） | 相等 |
| 关联 | `segment_id` | `source_segment_id` | 相等 |
| 数量 | N | N | 相等 |

### 4.2 单文件场景

| 条件 | 行为 |
|---|---|
| 仅 1 个回放片段 + 1 个回放文件 | 无需勾选操作（checkbox 不展示），自动视为完整回放 |
| 单文件场景的拼接按钮 | 始终可点击（仅校验所有文件已审核通过） |

## 五、发布前置条件（BR-AUDIT-030）

### 5.1 先审后拼

| 前置条件 | 拼接按钮状态 |
|---|---|
| 所有 ReplayFile.review_status = approved | ✅ 可点击 |
| 任一文件 review_status = pending_review 或 rejected | 🔒 锁定，提示「需先将所有回放文件审核通过」 |

### 5.2 先审后发

| 前置条件 | 发布按钮状态 |
|---|---|
| 所有文件已审核通过 + 拼接已完成 + 未发布 | ✅ 可点击 |
| 上述任一条件不满足 | 🔒 锁定，提示具体原因 |

## 六、流程图（v2.0.0）

```
[直播中] 检测断流 > N秒 → 切片段，segment_index++
     ↓
[直播结束] 状态 live → ended
     ↓
[生成片段+文件] 系统自动生成所有 ReplaySegment + ReplayFile（review_status=pending_review）
     ↓
[① 文件审核] 运营在回放页逐个点「审核通过」
     ├─ 拒绝 → 该文件标红，不参与拼接
     └─ 全部通过 ↓
[② 勾选对应] 运营勾选序号一一对应的片段+文件
     ├─ 单文件场景 → 自动跳过
     └─ 多文件场景 → 集合 size 相等 + index 完全相等 ↓
[③ 拼接] 系统校验 + FFmpeg concat → 完整文件（merge_status=completed）
     ├─ 失败 → merge_status=failed，提示运营
     └─ 成功 ↓
[④ 审核-发布] 运营点「发布」→ 回放对租户/观众可见生效
     ↓
[发布] 回放对用户可见
```

### 关键顺序铁律（v2.0.0）
- **逐个审核**（片段/文件独立，不批量）
- **先全部审核 → 再勾选对应 → 再拼接**（不颠倒）
- **拼接完成 → 才可发布**（不跳过）
- **拒绝不可参与拼接**（红线）

## 八、与擦音/审核的关系

| 维度 | v1.0.0 自动模式 | v2.0.0 手动模式 |
|---|---|---|
| 拼接触发 | 直播结束即自动触发 | 运营在回放页点「拼接」按钮 |
| 拼接校验 | 无需校验（系统自动拼接） | 必须所有文件审核通过 + 勾选对应 |
| 文件审核 | 无 | 每个文件独立审核通过后才可拼接 |
| 发布触发 | 人工审核通过自动发布 | 拼接完成后由运营点「发布」 |
| 错误处理 | 失败自动重试 → 标记 failed | 校验失败直接锁定按钮，运营无需等待 |
| 适用场景 | 单一流程，少量人工干预 | 复杂场景，需运营细粒度把控 |
