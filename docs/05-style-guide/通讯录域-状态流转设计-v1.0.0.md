## §0 状态机总览（纯函数，3 核心 + 6 辅助）

### SM-1 好友申请状态机 `im-friend-machine.ts`

```
                 ┌──────────────────────┐
                 │   pending_approve    │  ← 别人申请我（接收方视角）
                 │   (待通过)           │
                 └──┬────────┬──────────┘
          APPLY    │APPROVE │ REJECT
            ↓       ↓        ↓
        ┌──────┐ ┌──────┐ ┌──────────┐
        │waiting│ │added │ │ rejected │
        │等待验证│ │已添加│ │ 已拒绝   │
        └──┬───┘ └──────┘ └────┬─────┘
   APPROVE │                   │ REAPPLY (24h内≤3次)
           ↓                   ↓
        ┌──────┐          ┌──────────┐
        │added │          │ waiting  │
        └──────┘          └──────────┘
```

| 当前状态 | 事件 | 目标状态 | 触发场景 |
|---------|------|---------|---------|
| `waiting` | APPROVE | `added` | 对方通过申请 |
| `waiting` | REJECT | `rejected` | 对方拒绝申请 |
| `rejected` | REAPPLY | `waiting` | 再次申请（24h内≤3次） |
| `pending_approve` | APPLY | `waiting` | (保留) |
| `pending_approve` | APPROVE | `added` | 我通过对方申请 |
| `pending_approve` | REJECT | `rejected` | 我拒绝对方申请 |

**`added` 为终态（不可逆转，只能删除关系重建）**。`rejected` 可再申请。

### SM-2 群状态机 `im-group-machine.ts`（v3.0 两态）

```
           ┌──────────┐  STORE_DELETE /
           │  normal  │  OWNER_DISSOLVE /
           │  正常    │  DISABLE_DISSOLVE
           └────┬─────┘
                ↓
           ┌──────────┐
           │dissolved │  ← 终态，不可恢复
           │ 已解散   │
           └──────────┘
```

| 事件 | 说明 |
|------|------|
| `OWNER_DISSOLVE` | 群主在群设置中主动解散（App 端唯一解散途径） |
| `DISABLE_DISSOLVE` | 后台禁用门店时选择「同时解散群」（BR-IM-024） |
| `STORE_DELETE` | 门店删除 → 群解散 |

**关键规则**：
- 门店禁用/启用**不影响群**（除非明确选「同时解散」BR-IM-024）
- 换绑=群成员转移，**不改变群状态**（BR-IM-025）
- 无 90 天沉睡托管/归档只读（本期移除，D12）
- `dissolved` → 聊天页仅可查看，输入区禁用

### SM-3 售后单状态机 `im-aftersale-machine.ts`

```
    ┌──────────┐  ACCEPT    ┌────────────┐  COMPLETE   ┌──────┐
    │ pending  │ ────────→  │ processing │ ─────────→  │ done │
    │ 待处理   │            │  进行中    │             │已完成 │
    └────┬─────┘            └─────┬──────┘             └──────┘
         │ CLOSE                  │ CLOSE
         ↓                        ↓
    ┌──────────┐            ┌──────────┐
    │  closed  │ ←── CLOSE ─│  closed  │
    │ 已关闭   │            │ 已关闭   │
    └──────────┘            └──────────┘
```

| 当前状态 | 事件 | 目标状态 | 触发场景 |
|---------|------|---------|---------|
| `pending` | ACCEPT | `processing` | 店员接单开始处理 |
| `pending` | CLOSE | `closed` | 直接关闭（二次确认） |
| `processing` | COMPLETE | `done` | 退款完成/退货收货退款 |
| `processing` | CLOSE | `closed` | 关闭（二次确认） |
| `done` | — | — | 终态 |
| `closed` | — | — | 终态 |

**服务独占**（BR-IM-018）：处理中被其他店员锁定的售后单，当前店员仅可查看。

## §2 关键跨页面状态流转路径

### 路径 A：好友添加全链路

```
[ContactsPage] → [AddFriend]
  → 搜索手机号 → 选择用户 → 打招呼 → APPLY → status: waiting
  → redirect [FriendRequests]（出现在 waitingRequests 列表）
  
对方视角：[FriendRequests] pending_approve 列表
  → [通过] → APPROVE → status: added
  → click → [FriendProfile] → [发消息] → [ChatPage] (c2c-{userId})
```

### 路径 B：客户咨询 → 售后全链路

```
客户视角（ChatPage 客服群）:
  [订单] → 订单选择器 → 选订单 → [我要咨询此订单]
  → submitOrderConsult → 建售后单 status: pending
  → 卡片回写 aftersale_status: pending
  → 店员通知 (notify type: order_card_new)

店员视角（ChatPage 客服群）:
  click 订单卡片 → [AftersaleDetailPanel] (status: pending)
  → [开始处理] → ACCEPT → processing
  → [仅退款] → 填写金额/原因 → [确认退款] → COMPLETE → done
  或 → [退货退款] → 分步同意/收货 → COMPLETE → done
  → 卡片 aftersale_status 联动更新 done

客户视角：
  click 卡片 → [AftersaleDetailPanel] (只读视图)
  → 查看进度/售后记录
```

### 路径 C：询问卡确认链路（店员发起）

```
店员视角（ChatPage 客服群）:
  [客户订单] → 选客户订单 → [发送询问] → sendOrderInquiry
  → 询问卡入群 (card_role: inquiry, confirm_status: pending)
  
客户视角：
  → [是这笔] → confirmInquiry(true) → 建售后单 → card_status: confirmed
  → [不是] → confirmInquiry(false) → card_status: rejected
```

### 路径 D：直播 → 群发链路

```
店员/店长视角：
  [ChatPage] ⊕面板 → [直播] → startRoom → [ImLiveRoom]
  或 [LivePromoPage] → 选中直播间 → [分享]
    → 选择目标（按群聊/按个人/全部客户）
    → [发送] → 频控检查
      → doSend → live_card 发送到目标会话
      → 发送回执（成功/失败数）
      → [查看群发记录] → [MassSendRecordsPage]

客户视角（目标会话 ChatPage）：
  收到 live_card → click → [ImLiveRoom] (via=mass_send&batch)
  → 归因：mass_send_store 记录 click_count
```

### 路径 E：扫码邀请入群链路

```
店员/店长视角：
  [GroupSettings] → [添加成员] → 二维码邀请
    → [复制邀请链接] → 分享链接
    → [扫码预览] → new tab [JoinGroupPage]

客户视角：
  扫码/点击链接 → [JoinGroupPage]
    → [确认加入] → autoJoin + 绑定归属人
    → redirect [ChatPage] (进入客户群)
```

### 路径 F：联系客服建群链路

```
客户视角：
  [ConsultEntryPage] 商品详情/订单详情
    → [联系客服] → startConsult(customerId, store_id)
      → 幂等检查：已有客服群 → 直达 [ChatPage]
      → 无客服群 → 创建 store_service 群（群主=归属服务者）
        → redirect [ChatPage]
```

### 路径 G：绑定入群链路

```
客户绑定生效 → onCustomerBound
  → [PayResultPage] (joinState: loading)
    → 自动入群逻辑
      → 新客：创建 staff_group → joinState: created
      → 老客：复用已有群 → joinState: existing
      → 失败：补偿任务 → joinState: failed
    → [进入群聊] → [ChatPage]
```

## §5 设计决策说明

1. **已拒绝状态**（rejected）：暂不处理拒绝后再申请的交互限制（如拒绝理由展示、拒绝后隐藏入口等）。当前仅保留状态机流转能力。
2. **好友删除**：删除即关系销毁（本地聊天记录清除），若后续再加需走完整申请流程。
3. **群解散**：终态不可恢复，聊天记录归档保留（策略期后清理）。
4. **售后关闭**：closed 为终态，不可恢复。需店员二次确认。
5. **直播群发频控**：同直播间同目标 10min 内不可重复发送。
