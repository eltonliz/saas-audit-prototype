# 19-APP设计-双身份框架-v1.0

> **依据**：用户梳理的 Axure 原型（SaaS 门店 App：店长/店员 + 普通用户双身份）+ 课程与营期域 PRD v2.0.0
> **定位**：课程业务并入 SaaS 门店 App 双身份框架，替代原「独立课程 App」的形态
> **状态**：设计基线 v1.0（待确认后落地原型改造）

---

## §1 双身份模型

| 身份 | 谁 | 进入方式 | 核心诉求 |
|---|---|---|---|
| **普通用户** | 学员/消费者 | 默认身份 | 发现课程、报名营期、学习拿激励 |
| **店长/店员** | 门店经营者 | 我的页「切换角色」 | 推广课程给客户、查看课程数据、经营客户 |

**身份切换**：「我的」页头像下方「店长 · 切换角色 ›」入口，切换后整个 App 的页面内容与入口随身份变化（参考原型 u29/u7）。

## §4 关键交互规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | 身份切换全局生效 | 切换后 Tab 内容、我的页、入口集合整体切换；切换记忆在本地 |
| R2 | 普通用户默认 | 未登录/无门店身份的用户恒为普通用户 |
| R3 | 店长/店员来源 | 由 SaaS 门店成员身份决定（店长/店员），App 内只做身份识别与切换，不做审批 |
| R4 | 课程推广物料 | 复制=课程编号；口令推广=文案+口令；分享推广=小程序卡片/链接（原型期模拟生成） |
| R5 | 推广归因 | 客户经店长/店员推广报名 → 归属该门店成员（承接 §10.2 归属规则，SaaS 客户域落归属） |
| R6 | 激励不变 | 学习激励（完课红包/答题红包/积分）与身份无关，普通用户学习即得 |
| R7 | 经营数据口径 | 工作台经营数据为门店维度订单/客户统计（SaaS 门店域数据，课程域不重复建设）；课程管理 Tab 内为课程维度学习/转化数据（课程域提供） |
