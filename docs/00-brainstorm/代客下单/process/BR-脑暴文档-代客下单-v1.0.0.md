## §1 背景与目标

百货商城原型 v1.3.9.0 新增了三条相关能力：**代客下单（店长/店员端小程序）**、**代付（他人支付）**、**后台订单详情展示代付人/代下单用户**。现需评估如何在现有 SaaS 后台（追伴）落地，重排原型结构，做到：不新建立账体系、复用 SaaS 已有的客户归属/门店/订单/支付/营销能力，仅做最小增量改造。

## §2 原型走查记录（v1.3.9.0，已确认事实）

v1.3.9.0 共 32 页，与代客下单直接相关 3 页：

### §2.1 代客下单（店长店员）【小程序端】

原始规则（逐条照录）：

1. 在店长/店员端，商品规格选择页面（首页和分类）新增【代客下单】功能；
2. 点击【代客下单】后，跳转至【代客下单】弹窗页面；
3. 【代客下单】弹窗页面：
   - ① 搜索框：支持根据输入会员昵称/ID 搜索具体的会员；
   - ② 显示**该店长/店员归属的**会员头像、昵称/ID，单选一个会员进行代客下单；
   - ③ 点击【去下单】跳转至确认订单页面；
   - ④ 点击右上角关闭图标关闭弹窗；
   - ⑤ 若当前店长店员身份下没有会员，显示：暂无数据；
4. 跳转至确认订单页面，提交订单进行支付，支付完成后，**该订单客户信息为选择代客下单的会员**；
5. 若店长店员操作代客下单提交订单后未支付，**该笔订单会在对应店长店员后台显示出该订单信息**；
6. 到店自提形式：显示的自提点为**代下单会员绑定的店长店员归属的门店**；
7. 快递到家形式：收货地址默认显示为代下单会员名下的默认地址；进入选择地址页面显示该会员名下的地址；给该会员新增地址时，新增地址同步到会员收货地址名下。

### §2.2 代付功能

1. 小程序确认订单页点击【提交订单】→ 跳转【支付方式】选择页；
2. 支付方式页：文案「订单创建完成，请选择支付方式」；**本人支付（默认，走现有支付逻辑）/ 他人支付**；
3. 选择【他人支付】→ 跳转微信好友列表 → 发送商品支付卡片（商品名称 + 商品首图）→ 发送后返回待付款页；
4. 代付人点击商品卡片进入订单支付页（原型标注：**需确认能否无感登录，不能则先跳登录页再进支付页**）→【去支付】→ 收银台 → 支付成功；**代付人若非系统注册用户，不要求登录注册，不记录该支付人用户信息**。

### §2.3 【后台】订单管理

1. 后台-商城-订单管理-订单详情页：若该订单为代客下单/代付订单，详情页显示**代付人信息**与**代下单用户**；
2. 代付人信息：若代付人在系统中没有对应信息，则不显示；
3. 代下单用户：代客下单的用户昵称和 ID 信息。

原型详情页标注字段样式：`代付人信息 昵称（ID：12234）`、`代下单用户 昵称（ID：12234）`。

## §3 SaaS 后台走查记录（hhh 项目，已确认事实）

### §3.1 菜单结构

工作台 / 内容中心（素材）/ 应用管理 / 商品 / **交易（订单管理、售后管理、评价管理）** / **门店（门店管理、门店商品、门店成员、门店分组、门店账户、店员账户）** / 组织 / 设置 / 营销 / 课堂 / **客户（标签管理、会员等级、客户列表、黑名单客户、客户关系、公海客户）** / 直播 / 直播统计 / 财务 / 供应商 / 分佣管理 / 商城

### §3.2 订单管理列表（#/mallTrade/orderManagement）

- Tab：全部 / 待付款 / 待发货 / 已发货 / 售后中 / 已完成 / 已关闭；
- 筛选：订单编号、是否标星、是否留言；
- 批量操作：设置售后、批量分配门店、批量退款；
- 列：商品信息（订单号/商品/规格/数量/单价）、售后信息、实收金额（商品金额/邮费/优惠金额/积分抵现/应收金额/实收金额）、买家/收货人（昵称/收件人/电话/地址）、门店/配送方式、下单时间、订单状态（含支付方式与支付时间）、订单类型（销售订单）、买家备注、操作（详情/备注/发货/修改地址/分配门店）。

### §3.3 订单详情（列表内跳转详情视图）

- 订单编号 + 状态时间线（买家下单 → 交易关闭等）；
- 商家备注 / 买家备注；
- 信息区块：**收货人信息**（收货人/联系电话/收货地址）、**配送信息**（配送方式：快递发货）、**付款信息**（应付金额/实付金额）、**买家信息**（买家：昵称）、**营销信息**（满减/折扣/红包优惠总金额）；
- 商品信息表：商品（含商品编码/SKU）/ 单价 / 数量 / 单位 / 优惠后金额 / 售后状态 / 发货状态；
- 汇总：商品总价 / 优惠总价 / 积分抵扣（消耗积分）/ 订单应收总价。

### §3.4 客户列表（#/tenantCustomer/list）

- 关键列：客户编号、客户名称、手机号、会员等级、成长值、**所属门店、所属门店成员、门店成员身份**、客户来源、状态；
- 筛选已含：搜索门店、搜索所属店员；
- 即：**SaaS 已存在「客户 → 归属门店成员（店长/店员）→ 门店」的归属链**。

### §3.5 门店成员

- 列：编号（CY…）、名称、手机号、**角色（店长/店员）**、所属门店、**直接客户数**、审核状态、状态；
- 操作：邀请码 / 编辑 / 禁用 / 更换门店 / 转为客户 / 修改身份 / 添加账户。

### §3.6 其他相关

- 店员账户：为店员分账/钱包账户配置（主体类型/钱包账户 ID/商务号/商户密钥），属财务侧，不是员工门户；
- 工作台统计已有：待付款订单 / 待发货订单 / **待自提订单**（说明配送方式支持到店自提）/ 待处理售后；
- 支付方式现状：微信支付；订单类型现状：销售订单（单一枚举）。

### §3.7 现有 C 端（APP）下单页走查（2026-09-02，用户供图 4 张，已确认事实）

| 页面 | 现状结构 |
| --- | --- |
| 商品详情页 | 视频/图集轮播 + 价格卡（¥0.01 / 已售 33 / 领券）+ 规格行「选择 正红 >」+ 物流行「物流 快递 / 自提」+ 底部 店铺/客服/**立即购买**（绿色实心） |

| 确认订单（快递到家） | 页内 **tab 切换「快递到家 / 门店自提」** + 收货地址卡（可换）+ 门店商品卡 + 留言 + 金额区（商品总金额/**会员包邮权益**/运费/订单总金额/满减券/折扣券/积分抵现）+ 底部 应付金额 + **立即付款** |
| 确认订单（门店自提） | 取货地点卡「**请先选择附近自提点 >**」+ 提示「凭提货码到上方门店地址取货」+ 商品卡/金额区同上 |

**关键事实**：
1. 配送方式 = 确认订单页内 tab 切换，不在详情页/规格层选择；
2. 自提点 = 用户自选「附近自提点」，**无任何归属锁定**（Q4 裁决依据）；
3. **支付无中间页**：立即付款直达收银台 → 代付需在「立即付款」后新增支付方式选择步骤；
4. 优惠资格随买家（满减券/折扣券/积分抵现/会员包邮权益）。

## §5 重新梳理后的原型结构

### §5.1 总览（页面清单与跳转关系）

```
【小程序端 · 店长/店员身份】
P1 商品详情/规格选择弹层（首页+分类）
   └─【代客下单】(与"立即购买"并列)
P2 代客下单·会员选择弹窗 ──去下单──▶ P3
   └─ 空态：暂无数据；右上角关闭
P3 确认订单页（顶部代下单标识条）
   ├─ 自提：自提门店锁定（按 BR-06）
   ├─ 快递：默认会员地址/地址列表（会员名下）
   └─ 提交订单 ──▶ P4
P4 支付方式选择页
   ├─ 本人支付（默认）──▶ 收银台 ──▶ 支付成功
   └─ 他人支付 ──▶ 微信好友选择 ──▶ 发送支付卡片 ──▶ 返回 P5 待付款
P5 店长/店员端·待付款订单（名下待付款含代下单订单，支持催付）

【代付人侧（微信内打开）】
D1 代付订单支付页（商品名+首图+应付款）──去支付──▶ 收银台 ──▶ 支付成功
   （代付人非系统用户：不登录、不落用户表）

【SaaS 后台】
B1 订单管理列表（增量：下单方式/支付方式筛选 + 代单角标 + 所属店员筛选）
B2 订单详情（增量：「代下单信息」区块）
B3 客户详情（增量：该客户名下"被代下单"订单可见下单店员）
```

### §5.2 小程序端页面规格（V1.0.1 修订：对齐 §3.7 现有 C 端结构）

**P1 商品规格选择弹层（现有页增量）**
- 结构沿用现有规格弹层（商品图/价格/库存 + 数量步进器 + 色号标签）；
- 底部按钮由全宽「确定」改为**双按钮：「代客下单（主色描边）｜确定（主色实心）」**；
- 「代客下单」仅店长/店员身份渲染（会员身份仍是全宽确定，见 §8 BR-01）；
- 首页与分类两个场景共用同一弹层。

**P2 代客下单·会员选择弹窗**

```
┌──────────────────────────────┐
│  代客下单                  ✕  │
│ ┌──────────────────────────┐ │
│ │ 🔍 请输入会员昵称/ID      │ │
│ └──────────────────────────┘ │
│ ┌──────────────────────────┐ │
│ │ ○ 头像 会员昵称  ID：xxxx │ │  ← 数据源：当前店长/店员名下客户
│ │ ● 头像 会员昵称  ID：xxxx │ │     （客户.所属门店成员 = 当前操作者）
│ │ ○ 头像 会员昵称  ID：xxxx │ │  ← 单选
│ └──────────────────────────┘ │
│ [           去下单          ] │  ← 未选中置灰
└──────────────────────────────┘
空态：暂无数据（名下无会员）
```

**P3 确认订单页（沿用现有 tab 结构 + 代下单增量）**
- 页面骨架完全沿用现有确认订单页：**「快递到家 / 门店自提」页内 tab 切换 + 门店商品卡 + 留言 + 金额区（含会员包邮权益/满减券/折扣券/积分抵现）+ 底部 应付金额 + 立即付款**；
- 顶部新增**代下单标识条**（现有地址/取货卡片位之上）：`代客户下单：{会员昵称}（ID：{客户编号}）`，附「切换」可回 P2 重选；
- 快递到家 tab：默认收货地址 = 被代会员默认地址；地址选择页仅列该会员名下地址；新增地址保存到该会员名下（写库主语 = 被代客户）；
- 门店自提 tab：取货地点**默认带出被代客户「所属门店成员」所属门店的自提点（自动选中）**，仍可点「附近自提点」正常切换——不锁定（§8 BR-06 裁决方向）；归属门店行加「归属门店」标签便于识别；
- 优惠区按被代会员资格计算展示；
- 点「立即付款」→ P4（不再直达收银台）。

**P4 支付方式选择页（新增页，插入点 = 立即付款之后）**

```
┌──────────────────────────────┐
│ 订单创建完成，请选择支付方式   │
│ ◉ 本人支付   （默认）        │
│ ○ 他人支付                    │
│ [          立即付款         ] │
└──────────────────────────────┘
本人支付 → 现有收银台（微信支付，流程不变）
他人支付 → 微信好友选择 → 卡片（商品名称+商品首图）→ 返回待付款
```

- 该页是现有流程唯一「多一步」的改动：自助下单会员同样经过本页（默认本人支付，感知最小）；
- 可选优化（待确认 Q6）：仅代客下单订单显示本页，会员自助下单保持直达收银台。

**P5 店长/店员端待付款订单**
- 列出与本店长/店员相关（本人操作代下单 + 名下客户订单）的待付款订单；
- 操作：催付（复制支付链接/再次分享）、代付入口。

**D1 代付人支付页**
- 展示：商品名称、商品首图、应付款金额、【去支付】；
- 无感登录问题为原型遗留项 → 见 §12 待确认项 Q1。

### §5.3 SaaS 后台改造规格

**B1 订单管理列表（增量）**
- 筛选区新增：下单方式（全部/客户自助下单/店员代客下单）、支付方式（全部/本人支付/他人支付）、（复用现有门店筛选下）所属店员；
- 列表列「订单类型」由单一「销售订单」扩展展示：`销售订单·代客下单`；商品信息卡右上角加「代」角标；
- 待付款 Tab 即承载「代下单未支付订单在后台显示」的诉求（店员口径见 §8 BR-05）。

**B2 订单详情（增量：新增「代下单信息」区块，插于「买家信息」之后）**

```
┌ 代下单信息 ─────────────────────────────┐
│ 下单方式：店员代客下单                    │
│ 代下单用户：{店长/店员名称}（编号：CY…） │  ← 必显示
│ 所属门店：{门店名称}                      │
│ 代付人：{昵称}（客户编号：…）             │  ← 系统内无信息则整行不显示
│ 支付方式：他人支付 / 本人支付             │
└─────────────────────────────────────────┘
```

- 原型中「代付人信息 昵称（ID：12234）」对应 SaaS：代付人 = 客户编号；代下单用户 = 门店成员名称 + CY 编号（SaaS 无「用户 ID:12234」这种短 ID，须用现有编号体系，见 §12 Q3）；
- 付款信息区块不变（应付/实付），他人支付的流水号照常展示于支付流水。

**B3 客户详情（轻增量）**
- 客户详情订单 Tab 中，被代下单订单展示「下单店员」标记，便于归属核对。

## §6 数据契约建议（增量字段）

订单主表扩展（不新增表、不新建立账）：

| 字段 | 类型/枚举 | 说明 |
| --- | --- | --- |
| order_place_type | self / proxy | 客户自助下单 / 店员代客下单；默认 self |
| proxy_operator_id | 门店成员编号（CY…） | 代下单操作者；self 时为空 |
| proxy_operator_name | string | 冗余展示名 |
| proxy_operator_store_id | 门店 ID | 操作者所属门店（自提锁定用） |
| pay_mode | self_pay / others_pay | 本人支付 / 他人支付；默认 self_pay |
| proxy_payer_id | 客户编号（可空） | 代付人为系统用户时落库；否则置空（不记录） |
| pay_card_snapshot | JSON（商品名/首图） | 他人支付卡片内容留档，供对账 |

支付流水：他人支付时流水与订单正常关联；付款人非系统用户仅记支付渠道流水号（与原型「不记录该支付人的用户信息」一致）。

## §7 业务规则（BR）清单

| 编号 | 规则 |
| --- | --- |
| BR-01 | 【代客下单】入口仅店长/店员身份可见；会员身份不可见不可用 |
| BR-02 | 会员选择弹窗数据源 = 当前店长/店员名下客户（客户.所属门店成员 = 操作者），不支持跨店员/跨门店选人；名下无客户显示「暂无数据」 |
| BR-03 | 代客下单订单的买家 = 被代会员；优惠资格（优惠券/积分/等级价）按被代会员计算 |
| BR-04 | 代客下单提交订单未支付：订单进入待付款，并出现在操作者店长/店员的待付款视图（P5）与后台列表（按归属筛选口径） |
| BR-05 | 「店长店员后台显示」的口径建议 = 订单的操作店员（proxy_operator_id），而非会员归属店员；两者不一致时以操作店员为准（待确认 Q4） |
| BR-06 | **裁决方向（2026-09-02）**：现有 SaaS 下单页面无自提锁定；自提门店处理可参考原型逻辑（默认带出被代客户「所属门店成员」所属门店）但**不全部照搬**，保留用户可改自提点的既有交互，具体以结合 SaaS 业务产出的原型为准 |
| BR-07 | 快递到家：默认地址/地址列表/新增地址读写均以被代客户为主语；新增地址同步写入该会员地址簿 |
| BR-08 | 他人支付：卡片仅含商品名称+首图；代付人支付成功即核销待付款；代付人非系统用户不登录、不建用户、不记录其信息 |
| BR-09 | 代付成功后不可再本人重复支付（幂等）：待付款状态下生成支付单后，任一路径支付成功即关闭其余支付入口 |
| BR-10 | 逆向：代下单订单退款/售后走现有售后管理，款项按原路退回代付流水；代付人非系统用户时退款原路退回支付渠道，不落客户账户 |
| BR-11 | 代下单订单的「所属门店」统计口径与现有分配门店规则一致，不因代下单改变业绩归属门店 |

## §8 权限与角色

| 角色 | 能力 |
| --- | --- |
| 会员（C 端） | 自助下单、为待付款订单支付（本人支付）；不可见代客下单入口 |
| 店长/店员（小程序端） | 代客下单、查看名下待付款（含代下单）订单、发起他人支付分享 |
| 租户后台操作员 | 订单列表筛选/查看代下单信息、按现有流程发货/售后/退款 |
| 代付人（微信访客） | 仅支付被分享订单；无任何后台/订单列表权限 |

## §9 统计口径与对账

- 下单方式维度：新增「代客下单订单数/金额」统计，挂工作台或订单导出列；
- 他人支付：对账以支付渠道流水为准，代付流水与订单 1:1；代付人匿名订单在财务侧仅体现渠道流水；
- 退款冲减：按原支付流水原路退，不影响代下单/代付展示字段（保留历史）。

## §10 复用清单（不重复建账）

- 客户归属链（客户→门店成员→门店）、会员等级/成长值、优惠券/积分/满减折扣红包；
- 订单状态机（待付款/待发货/已发货/售后中/已完成/已关闭）与订单管理全部既有操作（备注/发货/修改地址/分配门店/售后）；
- 门店与自提、配送方式；微信支付收银台；售后管理/退款维权；
- 后台菜单不新增页面级入口（全部为现有页面增量字段/筛选/区块）。

## §12 验收标准（摘要）

1. 店长/店员在首页与分类的规格弹层可见【代客下单】，会员不可见；
2. 弹窗仅展示操作者名下客户，支持昵称/编号搜索，空态「暂无数据」；
3. 代下单订单支付成功后，订单买家为被代会员，详情出现「代下单信息」区块且字段正确；
4. 未支付代下单订单出现在操作店员待付款视图与后台待付款 Tab；
5. 自提单自提门店按 BR-06 锁定；快递单默认会员地址、新增地址写入会员名下；
6. 他人支付卡片可完成支付，非注册代付人不产生用户记录；重复支付被幂等拦截；
7. 退款原路退回，代付人匿名时退款走渠道流水。
