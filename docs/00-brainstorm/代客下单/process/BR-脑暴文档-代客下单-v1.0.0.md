## §1 背景与目标

百货商城原型 v1.3.9.0 新增了三条相关能力：**代客下单（店长/店员端小程序）**、**代付（他人支付）**、**后台订单详情展示代付人/代下单用户**。现需评估如何在现有 SaaS 后台（追伴）落地，重排原型结构，做到：不新建立账体系、复用 SaaS 已有的客户归属/门店/订单/支付/营销能力，仅做最小增量改造。

## §2 原型走查记录（v1.3.9.0，已确认事实）

### §2.1 代客下单（店长店员）【小程序端】

原始规则（逐条照录）：

1. 在店长/店员端，商品规格选择页面（首页和分类）新增【代客下单】功能；
2. 点击【代客下单】后，跳转至【代客下单】弹窗页面；
3. 【代客下单】弹窗页面：
   - ① 搜索框：支持根据输入会员昵称/ID 搜索具体的会员；
   - ② 显示**该店长/店员归属的**会员头像、昵称/ID，单选一个会员进行代客下单；
   - ③ 点击【去下单】跳转至确认订单页面；
   - ④ 点击右上角关闭图标关闭弹窗；
   - ⑤ 若当前店长店员身份下没有会员，显示：暂无数据；
4. 跳转至确认订单页面，提交订单进行支付，支付完成后，**该订单客户信息为选择代客下单的会员**；
5. 若店长店员操作代客下单提交订单后未支付，**该笔订单会在对应店长店员后台显示出该订单信息**；
6. 到店自提形式：显示的自提点为**代下单会员绑定的店长店员归属的门店**；
7. 快递到家形式：收货地址默认显示为代下单会员名下的默认地址；进入选择地址页面显示该会员名下的地址；给该会员新增地址时，新增地址同步到会员收货地址名下。

### §2.2 代付功能

1. 小程序确认订单页点击【提交订单】→ 跳转【支付方式】选择页；
2. 支付方式页：文案「订单创建完成，请选择支付方式」；**本人支付（默认，走现有支付逻辑）/ 他人支付**；
3. 选择【他人支付】→ 跳转微信好友列表 → 发送商品支付卡片（商品名称 + 商品首图）→ 发送后返回待付款页；
4. 代付人点击商品卡片进入订单支付页（原型标注：**需确认能否无感登录，不能则先跳登录页再进支付页**）→【去支付】→ 收银台 → 支付成功；**代付人若非系统注册用户，不要求登录注册，不记录该支付人用户信息**。

### §2.3 【后台】订单管理

1. 后台-商城-订单管理-订单详情页：若该订单为代客下单/代付订单，详情页显示**代付人信息**与**代下单用户**；
2. 代付人信息：若代付人在系统中没有对应信息，则不显示；
3. 代下单用户：代客下单的用户昵称和 ID 信息。

原型详情页标注字段样式：`代付人信息 昵称（ID：12234）`、`代下单用户 昵称（ID：12234）`。

- 关键列：客户编号、客户名称、手机号、会员等级、成长值、**所属门店、所属门店成员、门店成员身份**、客户来源、状态；

### §3.5 门店成员

- 列：编号（CY…）、名称、手机号、**角色（店长/店员）**、所属门店、**直接客户数**、审核状态、状态；

- 支付方式现状：微信支付；订单类型现状：销售订单（单一枚举）。

**关键事实**：
1. 配送方式 = 确认订单页内 tab 切换，不在详情页/规格层选择；
2. 自提点 = 用户自选「附近自提点」，**无任何归属锁定**（Q4 裁决依据）；
3. **支付无中间页**：立即付款直达收银台 → 代付需在「立即付款」后新增支付方式选择步骤；
4. 优惠资格随买家（满减券/折扣券/积分抵现/会员包邮权益）。

| 规格弹层 | 客户条置顶 + 商品/数量/规格 + **优惠券/配送费/配送方式直接在弹层内** + 合计 + 下单按钮（弹层即下单） |

**微赞模式 vs 百货商城原型模式**：
- 百货商城：**商品先行**（商品页发起 → 弹窗选会员 → 确认订单），入口埋在规格选择页；
- 微赞：**客户先行**（工作台/客户管理先锁定客户 → 商品列表选货下单），代客上下文全程提示条；
- 两者可并存：商品先行适合「看着商品帮客户下单」，客户先行适合「客户说帮我下个单」的场景。

## §5 重新梳理后的原型结构（V1.2.0：按用户指定主流程重梳）

> **用户裁决（2026-09-02 第二轮）**：主流程唯一 = 我的页面 → 工作台 → 客户管理（发放卡券旁加「代客下单」）→ 商品选择页 → 下单流程；原型按用户截图风格 1:1 复刻；逆向流对齐六域 PRD v7.0.0。原「规格弹层双按钮」入口（V1.0.x 通道A）**废弃**。

【店员端跟进与核销（工作台入口）】

### §5.2 页面规格要点（V1.2.0）

**P3 客户管理页（唯一入口）**
- 客户卡按钮行：`设为店员 | 设为黑名单 | 发放卡券 | 代客下单(新增)`；「代客下单」仅店长/店员可见；
- 点击即锁定该客户（跳过选人弹窗），进入 P4；
- 兼容声明：订单域 §1.4 明确「当前版本订单创建入口仅支持 APP 客户提交，门店开单为 Non-Goal」→ 代客下单为新增下单入口，**不新增订单状态**，完全复用现有状态机。

**P4 商品选择页（新增）**
- 顶部常驻锁定提示条「正在为 {客户昵称}（ID：{客户编号}）客户下单」+「退出」；
- 商品搜索 + 分类侧栏（复用现有分类）+ 商品卡「下单」；
- 上下文生命周期（BR-14）：提交订单/退出/30 分钟无操作自动解除。

**P6 确认订单（对齐用户截图）**
- 金额区行项 = 商品总金额 / 运费 / 订单总金额 / 选择满减券 / 选择折扣券 / 选择现金红包；
- 快递场景：默认被代客户名下默认地址，无地址显 P6b 空态（立即添加 → 写入被代客户名下）；
- 自提场景（现有 APP 已有自提 tab）：自提点默认逻辑结合 PRD 门店域 BR-STM-005（LBS 距离降序、商品自提点优先），代客时归属门店自提点置顶默认选中、可切换不锁定（BR-06）；
- 组合支付实付 = 应收 - 券 - 红包 - 积分（交易域 BR-TRD-006）；各优惠形式金额独立记录（订单域 BR-ORD-011，供逆向退回）。

**P10 店员端订单管理-待付款**
- 30 分钟倒计时（订单域 BR-ORD-004 超时自动关单、释放预占库存；硬编码 ORD-ISSUE-006）；
- 操作：催付 / 取消订单 / 代付-二维码；关单前 10 分钟推送店员提醒（新增建议）；已关闭代客单一键重下。

**P11 自提核销（对齐订单域 FN-ORD-004）**
- 店员/店长 APP 扫**客户提货码**（YXKSA+6 位）→ 反查整组提货单 → 勾选商品录应提/实提 → 支持部分提货 → 全部提货订单已完成；记录提货人/下单人/点货人；
- 代客扩展（BR-12）：客户报不出提货码时，店员经待自提列表核对身份后代客户端直接核销。

**逆向流 R1~R3（对齐 PRD）**
- 售后类型当前实现 = 仅退款/退货退款（换货/补发/部分退货 P1 待建，售后域 ENT-AFS-001）；申请前置：仅退款=已付款、退货退款=已签收；售后期 = 确认收货后 N 天（CONFIG-FIN-001）；
- 发起后订单挂起「售后中」（订单域 BR-ORD-005）；售后审核 30 分钟五场景自动处理（售后域 FN-AFS-006）；退款时效：自动 <1 分钟 / 人工 <24 小时；
- 退款原路退回：售后单 1:1 退款单经支付网关 refund（售后域 BR-AFS-006/007）；**三分支**见 BR-10；
- 券/红包按订单优惠独立记录退回；积分按退款比例退还（订单域 BR-ORD-011、交易域 BR-TRD-008、营销域 BR-MKT-010）；
- 佣金冲减：退款完成→佣金回滚（未结算暂停/已结算扣减，财务域 FN-FIN-009）；**代客单佣金归属=客户业绩归属人**（分销域 BR-DIS-004 永久锁客，Q8 据此关闭）。

| BR-19 | 防串单二次确认（V1.3.0 新增）：P6 点「立即付款」前强制弹确认层「确认为 {客户昵称}（ID 尾号 4 位）提交订单 ¥X？」（含客户头像+编号）；30 分钟内为不同客户连续下单时，确认层顶部对比提示「上一单客户：A ↦ 本单客户：B」；切换角色立即解除代客会话并返回我的页 |

| BR-15 | 待付款代客单权限矩阵（V1.1.0 新增，V1.3.0 补店长协同）：可见性=操作店员（P10）+ 被代会员（C 端我的订单，带「店员代下单」标识）+ 后台（下单方式筛选）；支付=操作店员（本人/他人）或被代会员（催付后自付，计 buyer_pay）；取消=操作店员（P10）或超时自动关单；催付=操作店员；**同门店店长=全权（可见/催付/取消/代改收货地址），同门店其他店员=只读+催付**（对齐 BR-12 核销的门店维度授权，交接班不产生孤儿单）；店员禁用/离职前名下待付款代客单自动移交店长；取消即时同步买家端并吊销已发分享 token；「一键重下」=携带原单 SKU+数量快照回到 P6、优惠实时重算、新单生成后原单打「已重下」标记，重下页展示原单/新单金额差异原因 |

## §9 统计口径与对账（V1.1.0 细化）

- 下单方式维度：新增「代客下单订单数/金额」统计，**双口径**=下单口径（含已关闭）与成交口径（实付），挂工作台或订单导出列；
- T+1 勾稽：渠道账单笔笔核销到订单（transaction_id ↔ out_trade_no）；付款人≠买家单按 pay_mode 打标；卡片金额≠实付的差异单进核查清单；差错流水（终态订单收到回调的自动退款、关单后支付成功冲正）单独建差错表，T+1 内处理完毕；
- 退款冲减：按 §7 BR-10 三分支执行；代下单/代付展示字段保留历史不覆盖；
- 导出模板（P2 起）：order_place_type / pay_mode / proxy_operator_id+name / 渠道 transaction_id / 退款流水号及去向，随他人支付链路同步上线，不留对账断档期；
- 发票/收据：开票主体=订单买家（被代会员），金额=实付金额，不因 pay_mode 改变（进 §13 Q9）。

## §12 验收标准（摘要）

1. **「我的→工作台→客户管理」链路仅店长/店员可达**；客户卡「发放卡券」旁出现【代客下单】按钮，会员身份全程不可见（V1.3.0 按唯一入口重写）；
2. 点击【代客下单】直接锁定该客户进入 P4 商品选择页，顶部提示条显示客户昵称+编号；店员视角列表仅名下客户渲染该按钮，店长视角为全店客户；
3. 代下单订单支付成功后，订单买家为被代会员，详情出现「代下单信息」区块且字段正确；
4. 未支付代下单订单出现在操作店员待付款视图（P10）与后台待付款 Tab，支持取消/催付；
5. **自提单默认自动选中归属门店自提点（带「归属门店」标签），可切换附近自提点，不锁定**（V1.1.0 修正，与 BR-06 对齐）；快递单默认会员地址、新增地址写入会员名下；
6. 他人支付卡片/二维码可完成支付，非注册代付人不产生用户记录；**重复支付：入口互斥 + 终态订单收到回调自动原路退款（差错流水可查）**；
7. 退款按 BR-10 三分支原路退回；垫付单退款向操作店员推送结清提醒；
8. **自助单回归（V1.3.0 补）**：会员自助下单点击「立即付款」直达收银台、不出现 P7，订单 pay_mode=buyer_pay、proxy 字段为空；支付单 1:N 改造后自助单全链路（下单→支付→退款→对账→导出）与基线一致；
9. **0 元单（V1.3.0 补）**：优惠后实付 0 元不走收银台直接置已支付并生成 0 元流水；0 元代客单禁用他人支付；优惠超应收截断至应收并落明细；
10. **自提核销（V1.3.0 补）**：扫客户提货码→反查提货单→部分提货→全部提货订单已完成；提货记录含提货人/下单人/点货人；重复核销/两店员并发核销被 CAS 拦截；
11. **边界与竞态（V1.3.0 补）**：倒计时 00:00 与支付回调竞态按 BR-09 兜底；token 剩余 ≤0 即失效；同客户并发重复提交按幂等键返回首单；「客户×店员」7 天 3 次代下退款触发 BR-20 冻结。
